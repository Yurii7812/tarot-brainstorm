# 引き継ぎ: タロット・ブレインストーミングアプリ

## 1. 経緯
ユーザーがウェイト版でヘキサグラム（7枚）を引き、その読みを AI と一緒に整理した。
その過程で、配置・画像・線の調整に何往復もかかったため、「効率的にカードを配置して、
効率的にブレインストーミングできるアプリ」を作りたい、という話になった。
まだアプリは作っていない。ここにあるのは、設計メモ、図の生成スクリプト、認識の実験。

## 2. 決まっていること（ユーザーの要望）
- スプレッドを選ぶと、位置と位置の意味が自動で入り、カードが自動配置される。
- 主要なスプレッドに対応する: 1枚、3枚（過去・現在・未来）、ヘキサグラム、ホースシュー、
  二者択一、ケルト十字。ケルト十字はウェイトの解説書そのものにある方式。
- カードの並びは「公式ウェイト版に同封の小冊子」と同じにしたい。
  - 暫定: 大アルカナ 0〜21（**力=8、正義=11**）→ ワンド → カップ → ソード → ペンタクル。
    各スートは エース〜10、ペイジ、ナイト、クイーン、キング。
  - 未確定: コートカードの順（小冊子の実物で確認する。設定で切り替え可能にする）。
- 入力はキーボード中心（カード名・略号を打つと画像が入る。リンクも打って作る）。
- 写真から認識して並びを入力する機能が欲しい（後段。第5節）。
- 使い方の想定: スプレッドを選ぶ → 並べる/撮る → 配置と意味の欄が埋まる → `.md` と画像を出力。

## 3. 設計に効く学び
- **位置の意味とカードの意味は別物。** 同じカードでも「相手の気持ち」の位置に出た時と、
  人物像として読む時で結論が変わる。位置の意味を読み違えて、解釈が一度ぶれた。
- 各カードに3つの入力欄を持たせる: ①標準の意味 ②この位置での読み ③自分の解釈。
- カード間のリンクには種類を付ける（流れ / ぶつかり）。図では灰色実線と赤点線にした。
- 同じ質問を短時間に何度も引き直せないようにする（履歴を残し、再抽選に間隔を設ける）。
  不安の処理のために引き直し続けることを避けるため。
- 画像のファイル名の罠: `Wands11=ペイジ, 12=ナイト, 13=クイーン, 14=キング`。
  最初に13をキングと取り違えて、クイーンの絵を載せた。大アルカナは `14_Temperance`, `15_Devil` のように番号付き。

## 4. データと権利
- カード画像: `assets/cards/rider-waite-720px/`（80枚。78枚＋余分2枚、720×1200）。
  出典は GitHub の `mixvlad/TarotCards`（Steve P. による1909年 Pam-A 版スキャンの修復版、パブリックドメイン）。
  詳細は `assets/SOURCES-from-repo.md`。
- ユーザーが持つのは U.S. Games 版（1971/2019 の著作権あり）。同梱するのは1909年版のみ。
  絵柄は同じだが色合いが少し違う。
- U.S. Games の小冊子の本文は著作物。アプリには同梱しない。並びと位置の名称は事実情報なので使える。
- 原書 *The Pictorial Key to the Tarot*（1911）の英文はパブリックドメイン。「標準の意味」欄に使える。
  日本語の翻訳・解説書の文章は著作権があるので、そのまま入れない。短い日本語の要約を書くか、空欄にする。
- 公開リポジトリのため、個人の読みが入った図（`out/`）と元の写真は含めていない。`prototypes/` のスクリプトを動かすと `out/` に例の図が生成される（文面は例）。
- `test-data/crops/` は、写真から切り出したカード7枚だけ（個人情報なし）。

## 5. 認識実験の結果（`recognition/`）
- 手法: OpenCV の SIFT 特徴量で、切り出した写真と80枚の参照画像を照合。
- 結果: 手で切り出した7枚が **7/7 で正解**。最も低かったのはワンドの8（照明の反射あり、一致38点、2位は8点）。
- 未実装:
  1. 写真からのカード検出・切り出し（机との色差で輪郭抽出が候補）
  2. スプレッドの位置への割り当て（ヘキサグラムなら、中心に最も近い1枚を結論、残りを角度で6分割）
  3. 逆位置の判定（参照画像を180度回した版とも照合して、点数の高いほうで決める）
  4. 点数が低い時は確定せず、候補3つを出して選ばせる
- 全部、端末内で動く（サーバー・通信不要）。

## 6. 図の生成スクリプト（`prototypes/`）
- `make_hex2.py`: ヘキサグラム配置＋リンク図（最終版）→ `out/spread_hexagram5.png`
- `make.py`: 元の配置（3×3風）＋リンク図 → `out/spread_map.png`
- Python + Pillow。日本語フォントは Noto Sans CJK JP（`/usr/share/fonts/opentype/noto/`）を前提。
- 位置・リンクの座標は手書き。アプリ本体ではスプレッドのテンプレート（座標＋位置名＋意味）に一般化する。

## 7. 未決事項
- コートカードの順、スプレッドごとの位置名（小冊子の写真があれば確定できる）。
- 形態: 単一 HTML のローカルアプリか、デスクトップアプリか。ユーザーは Linux 環境、ノートは `.md` 管理。
- 「標準の意味」欄: 原書の英文か、日本語の要約か、空欄か。

## 8. 最初の一歩（提案）
最小版: ヘキサグラム1種 + 78枚の名前入力 + 3層の入力欄 + リンクの作成 + `.md`/画像の出力。
認識はその次の段階。範囲は広げる前にユーザーに確認する。
